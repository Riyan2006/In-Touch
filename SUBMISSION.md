# In Touch

**Live demo:** [in-touch-beta.vercel.app](https://in-touch-beta.vercel.app/)

In Touch is a quiet relationship-pattern app. It notices a friendship getting quieter or a connection becoming more regular while the change is still small: meetups thinning before calls do, texts holding on the longest, or a person newly becoming part of the week. It is not a closeness score, a ranking, or a reminder to take action. It simply leaves a plain observation when a pattern has held.

Most “stay in touch” products are retrospective: they tell you a birthday is overdue or that you have not spoken to someone in a while. In Touch is anticipatory. It looks for the shape of sustained change in the rhythm of a relationship, so a drift or a forming friendship can become visible before it is obvious in hindsight.

The core is deliberately deterministic, not an LLM wrapper. A seeded Python generator creates twelve months of illustrative signals. For established contacts, the detector forms a four-month personal baseline, normalizes texts, calls, and meetups against their separate histories, combines them with transparent weights, and requires two consecutive threshold-crossing months before it flags a shift. New contacts use a separate cold-start rule: instead of a universal activity number, their reference is averaged from the user’s established relationships, with the old product defaults retained only when there are no established contacts to learn from.

The web demo begins with six pre-generated synthetic contacts. It also supports a local WhatsApp `.txt` import: Android and iOS export formats are parsed client-side into monthly message counts, message bodies are discarded immediately after local exclusion checks, and the result is visibly texts-only. The Android APK adds an on-demand Calendar meetup scan. It requests `READ_CALENDAR` only after the user starts it, matches attendees by email then name (with optional title matching), discards event details, and retains only monthly scheduled-meetup counts. WhatsApp and Calendar sources can be combined for one Android tracked person when their histories overlap. Calendar time is a record of planned time, not proof that a meeting happened.

The LLM layer is intentionally narrow: it turns only fired detections into one human-readable sentence. It rejects advice, scores, rankings, overly long responses, and multiple sentences. During optional data export it tries `gemini-3.5-flash`, then `gemini-3.1-flash-lite`, `gemini-2.5-flash`, and `gemini-2.5-flash-lite` only after temporary capacity/quota/availability failures; invalid prose gets one stricter retry, and any exhausted or non-retryable path becomes a logged deterministic fallback. On the deployed web app and APK, opening a fired report can call a Vercel-held Gemini key with only the aggregate values needed for that sentence—never message or Calendar content—and falls back locally if unavailable.

The complete project—generator, detector, tests, guarded Gemini integration, React/Vite interface, Android packaging, real-data import paths, persistence, themes, and visual work—was built in one continuous Codex session using GPT-5.6 (Terra/Luna) as the coding agent. The one exception is the optional generated insight wording itself, which uses Gemini for cost reasons. Its integration code, guardrails, fallback chain, and export wiring were also written through that same Codex/GPT-5.6 session.
